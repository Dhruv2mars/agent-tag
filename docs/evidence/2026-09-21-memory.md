## Checks run

The memory fixture created attributed entries in four scopes:

- `shared`: visible across profiles only when the viewing profile enables shared memory.
- `profile`: visible only inside the matching profile.
- `task`: visible only with the matching active task and profile context.
- `private`: visible only to the owner in a DM context when that profile enables private DM memory.

A second authorized identity could see the shared/profile/task entries available to its context but could not list or edit the first identity's private entry. A forged task context returned no memory. The owning identity edited an entry, incremented its version, forgot a task entry, and then the retention worker expired the remaining entries. Create, update, forget, expiry, and policy-denial transitions wrote structured audit records without memory content.

The coordinator projected authorized channel memory into the T3 user turn as JSON reference lines preceded by an explicit instruction to treat memory as untrusted context. Before external dispatch it stored the fully rendered turn text on the durable operation. A retry proposed different memory text but recovered the original snapshot, preserving byte-for-byte command replay semantics.

This evidence does not claim live Slack list/edit/forget controls, live DM routing, a human memory exercise, or semantic retrieval. Those remain required before `MEM-01` can pass.
