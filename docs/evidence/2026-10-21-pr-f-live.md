## How

`AGENT_TAG_LIVE=1 bun run scripts/live/pr-f.ts --config <throwaway config> --actor U0BSJQXNZDH` runs Agent Tag's own service loops (`AgentTagService` with one coordinator, the interaction worker, and the outbox delivering reactions, posts and `chat.update` edits through the real bot token), without Socket Mode, so the live service on the same Slack app keeps every event. The script posts each thread root as the bot, then injects the human's mention through the real `SlackEventRouter` and the Stop click through the real `SlackActionRouter`, using the Stop button value read back from the message in Slack. A recorder polls `conversations.replies` every 400 ms and keeps every distinct revision of every Agent Tag message; the checks run on that record and on the T3 snapshot.

Not covered here: Slack delivering the mention and the click over Socket Mode to the service. That path is unchanged by F4 and needs the live service upgraded to a build with F3.

## T3 checkpoint timing (why completion waits briefly)

Three probe turns on the same T3 (`claude-haiku-4-5`, two file edits each): the first snapshot with `latestTurn.state = completed` never had the turn's checkpoint; it appeared 212, 202 and 286 ms later (`status: ready`, 2 files). The coordinator therefore waits for the watcher's next event, at most 3 x 1 s, before settling without a file count.
