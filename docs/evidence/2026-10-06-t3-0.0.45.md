## Notes

- Root cause of the earlier Claude failures (`docs/evidence/2026-09-26-t3-rerun.md`): the Claude Code subscription login received HTTP 403 `oauth_not_allowed_for_organization` because of organization policy. T3 reported this as a generic Claude API error, and the live test classified it as `provider-api-errors`. T3 and the adapter were not at fault. Agent Tag now maps that text to `T3ProviderAuthPolicy` and signed-out credentials to `T3ProviderAuth`.
- One earlier run in this session failed only the Claude case, with `Claude usage limit reached`. That was an account limit. The passing run above happened after the limit reset.
- Earlier runs exposed a fixture-cleanup race. After `project.delete`, T3 `0.0.45` keeps pruning worktree metadata inside the fixture's `.git`, so a single recursive remove could fail with ENOENT. Every test body still passed. Cleanup now retries until the directory is gone.
- T3 `0.0.45` adds approval `requestKind` `"permission"` (legacy `permission_approval`). Agent Tag now surfaces these approvals. Before this change it skipped them silently, which stalled the turn.
