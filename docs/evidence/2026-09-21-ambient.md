# Ambient participation evidence, 2026-09-21

Actor type: `automated-fixture`

## System under test

- Agent Tag branch: `feat/t3-slack-spike`
- Platform: macOS `26.6.2`, arm64
- Slack boundary: the production `SlackEventRouter`

## Checks run

Ambient participation remained disabled under the default profile configuration. A routed top-level message without an explicit bot mention returned `ambient-disabled` and created no task or operation.

With explicit opt-in and the keyword `incident`, the fixture exercised six top-level messages. The first relevant message created a normal durable task operation. A different relevant message inside the configured cooldown stayed quiet. A whitespace/case-normalized repeat stayed quiet as unchanged even after the cooldown. A new relevant message after cooldown created the second operation. A third new relevant message stayed quiet after the hourly bound. An irrelevant message never entered the ambient decision log.

Every evaluated relevant message stored only a SHA-256 content fingerprint plus its trigger/quiet disposition and reason; raw message text remained in the ordinary authorized Slack inbox only when an operation was actually created. Triggered and quiet decisions wrote structured audits with `relevant`, `cooldown`, `unchanged`, or `hourly-limit` metadata.

This proves opt-in, configured relevance, unchanged suppression, cooldown, hourly bounding, durable retry decisions, and audit behavior in fixtures. It does not claim live channel behavior, semantic relevance, a long-running quiet observation, or a human exercise.
